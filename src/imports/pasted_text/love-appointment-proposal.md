LOVE APPOINTMENT — PROPOSAL WEBSITE
MVP PROJECT MAP
========================================

01. IDEA
--------

Core idea:
A private, interactive website that asks a crush a marriage-intention question in a playful way:

“Can I marry you in 2–3 years?
I’d like to book your appointment from now. 👀❤️”

The website behaves like a cute pixel-art appointment/booking system.

Experience:
Curiosity → Proposal → Playful interaction → YES → Appointment confirmation → Baba’s number → Final image reveal

Purpose:
Create a moment she remembers.

North-star question:
“Does this make the experience more cute, personal, and memorable?”

If not, cut it.


02. CONCEPT
----------

Working concept:
“Love Appointment” 💌

Concept:
Romance × Pixel Art × Fake Booking System

The humor comes from treating something emotional like a ridiculously serious appointment.

Tone:
- Cute
- Playful
- Slightly chaotic
- Romantic
- Personal
- Nostalgic
- Not overly cheesy

Avoid:
- Valentine’s Day template aesthetic
- Corporate booking website
- Generic proposal page
- Overloaded anime website
- 2012 glitter website
- Manipulative “you can’t say no” prank

06. SCREEN 03 — THE NO INTERACTION
----------------------------------

Main mechanic:
The NO button moves when she tries to select it.

Example messages:

First attempt:
“Are you sure? 🥺”

Second attempt:
“Think about it again 😭”

Third attempt:
“Really? 👀”

Fourth:
“You’re making this appointment difficult.”

YES button progressively grows.

Suggested scaling:
- Attempt 0 → 100%
- Attempt 1 → 115%
- Attempt 2 → 135%
- Attempt 3 → 160%

Important UX rule:
NO must remain possible.

The joke should be:
“Haha, the button is running away.”

Not:
“The website won’t let me reject him.”

Mobile:
Phones have no hover, so use touch/pointer interaction.

28. RESPONSIVE DESIGN
--------------------

Primary target:
390 × 844

Secondary:
768 × 1024

Desktop:
1440 × 900

Design mobile-first.

Desktop should be an expanded version of the mobile experience.


29. ACCESSIBILITY
-----------------

Include:
- Readable text
- Proper contrast
- Keyboard navigation
- Real buttons
- Visible focus states
- Form validation
- Reduced-motion support

The NO animation should not be excessive for users who prefer reduced motion.


30. PERFORMANCE
---------------

Target:
Under 2 seconds initial load where practical.

Optimize:
- Final image → WebP/AVIF
- Pixel assets → SVG/PNG
- Avoid unnecessary libraries
- Lazy-load final image if useful

Keep the website extremely lightweight.


31. PRIVACY / SECURITY
---------------------

Because the website collects a phone number:

Do not:
- Expose the number in frontend code
- Store it publicly
- Put it in URL parameters
- Save it unnecessarily in localStorage
- Create a public database

Do:
- Use HTTPS
- Use a secure form endpoint
- Keep access private
- Explain why the number is being requested
- Make sharing optional/comfortable

-------------------

Do not try to impress her with how much code was written.

Make the reaction:

“This idiot actually made an entire website just to ask me this.” 😂❤️

That is the win.

The strongest combination is:

Pink pixel aesthetic
+
Appointment-booking concept
+
Playful YES/NO interaction
+
Unexpected baba-number step
+
Final image reveal

Do not dilute it with unnecessary features.
